# Reviewer Handoff Guide

## Purpose
This project is a local-first OpenAI demo for a virtual board member named Morgan.

The capability ladder is implemented as:
1. Phase 1: OpenAI-connected baseline app with governance defaults.
2. Phase 2: Passive participant (listens, responds when invited).
3. Phase 3: Reactive contributor (raise-hand interventions).
4. Phase 4: Persona studio and fixed-perspective board roster.
5. Phase 5: Multi-agent shadow board simulation with report output.

Primary product brief: `docs/requirements/morgan-phase-brief.md`.

## End-to-End Flow Walkthroughs

### 1. Meeting Capture -> Invite Morgan -> SSE Hand Raise
1. UI starts a consent-gated meeting session via `POST /api/meeting/sessions` in `app/api/meeting/sessions/route.ts`.
2. UI requests an ephemeral realtime client secret through `POST /api/realtime/client-secret` in `app/api/realtime/client-secret/route.ts`.
3. Transcript chunks are posted to `POST /api/meeting/transcript-segments` in `app/api/meeting/transcript-segments/route.ts`.
4. Incoming transcript text is redacted (`lib/redaction/redact.ts`) before persistence.
5. Monitor evaluation runs in `lib/agents/monitor.ts` and may publish a hand-raise event over `lib/events/meeting-event-bus.ts`.
6. Clients consume events over SSE from `GET /api/meeting/events/:sessionId` in `app/api/meeting/events/[sessionId]/route.ts`.
7. Manual invite path uses `POST /api/meeting/invite-morgan` in `app/api/meeting/invite-morgan/route.ts`, backed by `lib/agents/invite-morgan.ts`.
8. Optional TTS clip generation is handled by `lib/audio/tts.ts` and served by `GET /api/meeting/audio/:fileName`.

### 2. Persona Interview Synthesis
1. UI starts interview with `POST /api/personas/interview/start` in `app/api/personas/interview/start/route.ts`.
2. Each answer is submitted to `POST /api/personas/interview/:id/turn` in `app/api/personas/interview/[id]/turn/route.ts`.
3. Interview flow and draft profile synthesis are implemented in `lib/agents/persona-interview.ts`.
4. Personas are persisted through `lib/store/repository.ts` and listed via `GET /api/personas`.

### 3. Shadow Board Run -> Report -> SSE Events
1. UI starts a run with `POST /api/shadow-board/runs` in `app/api/shadow-board/runs/route.ts`.
2. Async orchestration executes in `lib/agents/shadow-board.ts`.
3. Turn-level events are published by `lib/events/shadow-board-event-bus.ts` and streamed via `GET /api/shadow-board/events/:runId` in `app/api/shadow-board/events/[runId]/route.ts`.
4. Run state is fetched from `GET /api/shadow-board/runs/:runId`.
5. Markdown report is generated by `GET /api/shadow-board/runs/:runId/report` in `app/api/shadow-board/runs/[runId]/report/route.ts`.

## Governance Defaults
Runtime policy is controlled in `lib/config.ts` and `.env` values.

Default behavior:
- Consent is required before capture (`POST /api/meeting/sessions` rejects `consentAccepted=false`).
- Redaction is enabled by default (`ENABLE_REDACTION=true`).
- Transcript persistence is enabled by default (`PERSIST_TRANSCRIPTS=true`).
- Raw audio persistence is disabled by default (`PERSIST_RAW_AUDIO=false`).

Policy observability endpoint:
- `GET /api/demo/health`.
